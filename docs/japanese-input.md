# 日本語入力の設計メモ（ローマ字・かな配列は実装済み）

日本語のタイピングと日本語キー配列（月見草配列のように2キーの連続入力で1つのかなを入力する配列や、シフトを伴うキーストローク入力）を実装するための、設計の前提と論点の整理。**QWERTY のローマ字入力（3 の「最初の実装」）と、登録したかな配列での入力（3 の「かな配列の実装」）は実装した。同時押しのシフトなどは、まだ決まっていない。** 決まったことは、このファイルと `docs/measurement.md`・`docs/storage.md` などに反映していく。

出典の区別：
- **［確認可］** … コード・CLAUDE.md・`docs/*.md` で確かめられること
- **［会話のみ］** … これまでの検討の中で決めたことや、その理由（ほかに記録がない）

## 3. これまでに決めたこと（日本語入力に関係するもの）

- **［会話のみ］ IME を使わない**：変換中の文字が何度も書き換わり、打鍵の記録や判定ができなくなるため。多くのタイピング練習と同じ方式にする。
- **［会話のみ］ ランキングは配列ごとに分ける**：配列が違う記録を同じ順位で比べても意味がないため（区分は言語・モード・配列）。
- **［会話のみ］ keyLayout は論理配列**：どの文字がどのキーにあるか（QWERTY・Dvorak・かな配列など）を表す。物理配列（JIS・US）とは別。物理配列も区別したくなったら、別の項目として足す。
- **［会話のみ］ 生データに keyLayout を入れる**：events は入力された文字なので、配列が分かれば文字を物理キーの位置に変換できる、という理由（ただし 4 の注意点を参照）。
- **［会話のみ］ 生データに text を残す**：直さない間違いがあると events からお題を復元できず、お題ファイルも後で変わりうるため。日本語でもこの考え方は同じ。
- **［会話のみ］ 判定の結果を events に残す**：判定ルール（ローマ字の複数の打ち方など）が後で変わっても、当時の判定が分かるようにするため。
- **［会話のみ］ 日本語のお題に「読み」が必要になったら形式を見直す**：お題を `.txt`（1行70文字前後で改行）にしたときに、そう決めていた。
- **［会話のみ］ 速さは「入力した文字数」と「キーストローク数」の両方で見る**：入力速度などを計算するときは、単位時間あたりの入力文字数と、単位時間あたりのキーストローク数の両方を考慮する。かな配列やローマ字では、1文字に必要なキーの数が配列や文字によって違うため、片方だけでは比べられない。
- **［会話のみ］ 日本語の文字数は「かな1文字」で数える**：お題の読み（かな）の文字数を数える。表示する漢字かな交じりの文の文字数は使わない。
- **［会話のみ］ 平均 IKI は「キーあたり」にする**：日本語では、1キーストロークあたりの時間を平均 IKI とする。かな1文字あたりの速さは、単位時間あたりの入力文字数（かな）として別に出す。
- **［会話のみ］ 最初に対応する日本語キー配列は月見草配列**。前置・後置シフトによる入力がある。
- **［会話のみ］ かなの割り当ては「キーの並び → かな」の表で設定する**：例 `{"j", "っ"}, {"j'", "ぴ"}, {"j'e", "ぴゃ"}`。前置シフト・後置シフト・3打以上の並びも、すべて1行で表せる。ローマ字も同じ形で書ける。
  - 表の中のキーは **US キーボードの QWERTY の文字**として読む（`'` は US の単独のキー）。
  - お見せいただいた形（`{"キー", "かな"},`）をそのまま読めるようにする。ほかのツールの表を貼り付けて使えるため。
- **［会話のみ］ 物理キーには「行＋列」の2桁の番号を振る**：行は数字の行が `0`、Q の行が `1`、A の行が `2`、Z の行が `3`、スペースの行が `4`。番号は「行番号＋列番号」で、**列番号は16進数**（1 から数え、9 の次は a, b, c, d, e, f。1行に最大15個）。2桁にそろえ、`1` と `11` の読み違えを防ぐ。数字の行の左端のキー（US の `` ` ``）は含めず、**「1」のキーを `01`、Q を `11`、A を `21`、Z を `31`** とする（P は `1a`）。ブラウザの `e.code`（物理的な位置を表す値）と1対1で対応づけ、OS の入力設定（US／JIS）に左右されないようにする。
- **［会話のみ］ 記録には押した物理キーの番号を残す**：かな配列では文字から物理キーを逆算できないため（4 を参照）。
- **［会話のみ］ 割り当ての確認表示に keyboard-layout-editor（https://www.keyboard-layout-editor.com/）の JSON を使う**：各キーの位置と大きさ（x・y・幅・高さ）を取り出し、自分のキーボードの形で表示する。JSON の各キーと番号は、**ラベルの一か所（例：左上）に番号（`11` など）を書いておく**ことで結び付ける。ラベルの文字（`Q` など）からの推測はしない。
- **［会話のみ］ 配列は利用者が画面から自分のファイルを読み込んで登録する**：割り当て表と keyboard-layout-editor の JSON を読み込む。一度登録した配列は IndexedDB に保存し、あとで編集・変更できるようにする。
- **［会話のみ］ 配列名に版を付ける**：`v2` のような文字を配列名に加える（例 `tsukimisou-v2`）。記録には版付きの配列名を残し、どの割り当てで打った記録か分かるようにする。
- **［会話のみ］ 記録の書き出し・読み込みに、登録した配列も含める**：別の PC に記録を移しても、記録を読み解けるようにするため。
- **［会話のみ］ 確定のタイミング**：連続して入力されたキーが、割り当て表のどの並びにも一致しなくなったときに、それまでに一致していた部分を確定する。例：`j` の次に押したキーを足すと、どの並びの始まりにもならないなら、`j` → っ を確定し、そのキーから次の並びを始める。
- **［会話のみ］ OS は US キーボード・英字入力の状態で使う**：OS の入力は US 配列の英字のまま（IME はオフ）にし、かなへの変換はすべて Typattern の中で行う。キーは `e.code`（押したキーの物理的な位置）で受け取る。
- **［会話のみ］ スマホ・タブレットには対応しない**：画面のキーボードでは `e.code` が正しく取れないため。README にも書いた。
- **［会話のみ］ JIS の ¥ キーは US の `1d` として読み替える**：US キーボードではかな入力に ¥ キーは要らないが、JIS のかな入力では使う。US 配列では Q の行の右端の `\` のキー（`1d`）がこれに当たるので、JIS キーボードの ¥ キー（`e.code` は `IntlYen`）は `1d` として扱う。
- **［会話のみ］ JIS の「ろ」キーは `3b` とする**：Z の行の `/`（`3a`）の右にあるので、同じ考え方で続きの番号にする（`e.code` は `IntlRo`）。
- **［会話のみ］ Shift キーは左を `30`、右を `3c` とする**：左 Shift は Z（`31`）の左なので列 `0`。右 Shift は JIS では「ろ」（`3b`）の右にあるので `3c`。US キーボードには「ろ」がなく `3b` は空きになるが、右 Shift の番号は配列によらず `3c` に決めておく。
- **［会話のみ］ events に「キーを押した」行 `"k"` を足す**：今の決まり（どの行も5要素）に合わせる。キーの単位（`"k"`）とかなの単位（`"+"` / `"-"`）の両方を1本の記録に残す。**英語のタイピングでも `"k"` の行を残す**（英語でも Shift を含めたキーあたりの IKI とキーストローク数が出せ、記録の形が言語によらず同じになる）。
  - `[経過ms, "k", 物理キーの番号, かなの位置, 判定]`：キーを押すたびに1行。番号は `e.code` ではなく物理キーの番号（¥ を `1d` とする読み替えなども記録の時点で済ませる）。かなの位置は、お題の何文字目（かな）を打っている途中か。判定はそのキーが正しかったか（1/0）。Backspace も `"k"` の行にし、判定は `null`。
  - `[経過ms, "+", 文字, 文字の位置, 判定]`：文字（日本語はかな）が確定したときに1行。**時刻は言語によらず「その文字を生んだ最後のキーの時刻」**と定義する。英語は1文字が1つのキー（大文字は Shift ＋ キーで、最後はそのキー）なので、そのキーの時刻。日本語はかなの最後のキーの時刻（後置シフトのように次のキーで確定する場合も、確定した瞬間ではない）。そのため日本語では、行の並び順と時刻の順が一致しないことがある（分析では時刻で並べ直す）。
  - `[経過ms, "-", かな, かなの位置, null]`：確定したかなを Backspace で消したときだけ残す。打ちかけ（未確定）のキーを消したときは `"-"` を出さない。
  - キーの IKI は `"k"` の行どうしの時間の差、かなの速さは `"+"` の行から求める。
  - 例（お題「しか」をローマ字で `shika`）：

    ```
    [  0.0, "k", "22", 0, 1]   s
    [150.2, "k", "26", 0, 1]   h
    [290.5, "k", "18", 0, 1]   i
    [290.5, "+", "し", 0, 1]   「し」が確定
    [420.0, "k", "28", 1, 1]   k
    [530.8, "k", "21", 1, 1]   a
    [530.8, "+", "か", 1, 1]   「か」が確定
    ```

  - 例（月見草配列の後置シフト。お題「ぴ…」を `j` → `'` → 次のかなのキー）：

    ```
    [  0.0, "k", "27", 0, 1]   j
    [120.0, "k", "2b", 0, 1]   '
    [260.0, "k", "28", 1, 1]   次のかなのキー（「j'」の続きではないと分かる）
    [120.0, "+", "ぴ", 0, 1]   ここで「ぴ」を確定。時刻は最後のキー（'）の時刻
    ```

- **［会話のみ］ schemaVersion を 4 に上げ、3 以前の記録は扱わない**：`"k"` の行（キーの記録）があることと、`"+"` の時刻の定義を、版で明確にするため。schemaVersion 1 のときと同じく、新しい保存場所（データベース）を使い、3 以前の記録は読まない（消しもしない）。3 以前の書き出しファイルも読み込まない。これまでの記録は少ないので、新しく始める。
- **データ量の見積もり**（1回 約300文字、1行 約22〜25バイト）：英語は events 約620行・生データ全体 約17KB、日本語のローマ字は約800行・約22KB、月見草配列は約700行・約19KB。1日10回を1年続けて約70MB で、IndexedDB の容量には十分に収まる。実装したら実際の記録で確かめる。
- **［会話のみ］ 同時押しのシフトは今は実装しない**：今後の課題とする（5 を参照）。今は前置・後置シフトなど、順番に押す入力だけを扱う。

### 最初の実装（QWERTY のローマ字入力）で決めたこと

- **［会話のみ］ 判定はお題に合わせる**：打つべきかなを読める打ち方の一覧（例「し」= shi・si・ci）を割り当て表から作り、押したキーがそのどれかの続きなら正解とする。「ん」を `n` 1つで打てるか（次のかなが母音・ナ行・ヤ行で始まらないとき）、「っ」を子音の重ね（`kk` など）で打つかも、お題を見て決める。表だけで機械的に変換すると `konnichiha` が「こんいちは」になるため。月見草配列でも同じ仕組みを使う。
- **［会話のみ］ 間違えたキーは英語と同じく残す**：打ち方の一覧のどれの続きにもならないキーを押したら、そのかなを間違いとして確定し、次のかなに進む。Backspace で消して打ち直す。正確率は英語と同じく「(かなの数 − 未修正の間違い) ÷ かなの数」。
- **［会話のみ］ 日本語の平均 IKI ＝ 経過時間 ÷（正しく打ったキーの数 − 1）**：ミスにかかった時間も遅さに含まれる。かなの速さは「かな/分」として括弧で出す（英語の WPM に当たる）。英語の平均 IKI は今の式（文字あたり）のまま。
- **［会話のみ］ お題ファイル**：1つの `.txt` に「表示する文」と「読み（ひらがな）」を1行ずつ交互に書く。読み込むときは行をつなげ、日本語ではスペースを入れない。お題には Shift を使う文字を入れず、記号は「、」「。」「ー」だけにする。
- **［確認可］ 実装（段階3）**：判定は `js/romaji.js`、キーの受け取りは `js/app.js` の `handleJaKey`。計測ルールは `docs/measurement.md` の「日本語（ローマ字入力）」。events の使い方：
  - `"k"` の位置は、そのキーを当てたかなの位置。打ちかけの `n`（ん）が次のキーで確定したときは、次のキーの位置は次のかな。
  - `"+"` の文字は**お題のかな**（間違いのときも、打ったキーではなくお題のかなを入れ、判定を `0` にする。何を押したかは `"k"` の行で分かる）。時刻はそのかなを生んだ最後のキーの時刻。
  - Backspace は、打ちかけのキーを消したときは `"k"` だけ、確定したかなを消したときは `"k"` と `"-"`。「しゃ」を `sha` で打った後の Backspace は、2文字とも消える（`"-"` の文字は「しゃ」）。
  - 間違えたキーは、それまでの打ちかけのキーと一緒に「間違えたかな」1文字として確定する。Backspace で消すと、そのかなを最初から打ち直す。
- **［確認可］ 段階4**：n-gram は、英語も日本語も押したキーの組で数え、QWERTY の文字で表示する（Shift と同時に押したキーは除く。`docs/analysis.md`）。結果画面の「キーごとの間隔」は、日本語では押したキーごとの間隔（キーは QWERTY の文字、下の段にかな）で、どのかなの後でも折り返し、「。」の後で改行する（`docs/measurement.md`）。推移では、英語と日本語が混ざると凡例に注意を出す（`docs/records.md`）。
- **［確認可］ schemaVersion 4 の記録は新しいデータベース `typattern-records` に保存し、書き出しファイルの `app` は `"typattern"`**（`docs/storage.md`）。英語の `"k"` の行も記録し始めた。スペースの番号は仮に `45`（JIS の下の行の並び：Ctrl 41・Win 42・Alt 43・無変換 44・スペース 45）。

### かな配列の実装で決めたこと

キー配列のページの決まりは `docs/layouts.md`、タイピング画面の判定は `docs/measurement.md` の「かな配列」、保存形式は `docs/storage.md`。

- **［確認可］ キー配列のページ**（`layouts.html`）で、配列図・試し打ち・割り当て表の登録をする。試し打ちは最長一致で変換し、Enter で打ちかけを確定する。
- **［会話のみ］ キーボードの形は配列とは別に選ぶ**：3 では「keyboard-layout-editor の JSON を配列ごとに読み込む」としていたが、物理的な形は選べるようにして（今はロースタッガードの US 配列だけ、`js/keyboard-shapes.js`）、配列ごとには持たないことにした。keyboard-layout-editor の JSON を読むかは今後。
- **［会話のみ］ 確認表示**：1つのキーに、表示中のシフト面のかなと Shift ＋ そのキーのかなを書き、シフト面（自動・シフトなし・前置シフト・後置シフト）を切り替えて見る。「段」と呼ぶと50音の「あ段」などと紛れるので、「シフト面」と呼ぶ。
- **［会話のみ］ 配列名と版は利用者に任せる**：アプリは版を付けない。同じ名前で保存し直すときは確かめてから上書きし、その配列で打った記録があれば上書きはできない。削除はでき、記録は残して「配列名（削除済）」と出す。最初から入っている `qwerty` の名前は使えない。編集は、割り当て表を読み込み直して保存し直す（画面上で1行ずつ直す機能はない）。
- **［会話のみ］ 割り当て表のかなはローマ字でも書ける**（例 `j xtu`）。読み込むときにかなに直して保存する。割り当て表でよく使われる `txu` も「っ」と読む。区切りはタブ・スペース（いくつ続いてもよい）か、`{"j", "っ"},` の形。
- **［会話のみ］ 書き出しファイルに配列を入れる**：`layouts` を足した（項目の追加なので schemaVersion は 4 のまま）。読み込み先に同じ名前で中身の違う配列があれば、今のものを残して知らせる。保存場所を足したので `DB_VERSION` を 2 にした。
- **［会話のみ］ 判定はローマ字と共通**（`js/typer.js`）：割り当て表を逆に引いて、お題のかなを打てる並びの一覧を作り、お題に合わせて判定する。後置シフトも、お題が分かっているので迷わない。
- **［会話のみ］ 割り当て表にないかなは、ミスとして飛ばす**：配列が不完全なため。その位置で1回だけミスに数え、未修正の間違いとして残る。
- **［会話のみ］ かな配列のときは手引き（次に打つキー）を出さない**。お題の読みはひらがなのまま。
- **［会話のみ］ 配列の項目**：入力方式を別の項目にはせず、`keyLayout` に `"qwerty"`（日本語ならローマ字入力）か配列名を入れる。英語ではかな配列を選べない。記録ページの配列の絞り込みには、登録した配列と、登録を消した配列（「名前（削除済）」）も出す。

## 4. 注意点・未解決の問題

- **かな配列では、文字から物理キーを逆算できない**：2キーで1かなになる配列やシフト入力では、1文字に複数のキーが対応する。押したキー（`e.code`、シフトの状態）そのものを記録する必要がある。 3 の「keyLayout があれば変換できる」は英字の QWERTY にしか当てはまらない。→ 記録には押した物理キーの番号を残すことに決めた（3 を参照）。
- **入力の受け取りの作り替えが必要**：「input イベントで1文字＝1打鍵」の前提は使えない。→ **解決済み**：日本語は keydown の `e.code` で受け取り、IME がオンのときは受け付けない（`docs/measurement.md`）。
- **［確認可］ お題の改行の扱い**：英語のお題は、改行や連続した空白をスペース1つにまとめて読む。→ **解決済み**：日本語は行をスペースなしでつなげる（CLAUDE.md）。
- **［確認可］ スペースを前提にした処理**：キーごとの間隔のグラフはスペースの位置で折り返し、n-gram はスペースを含むものを除く。→ **解決済み**：日本語のグラフはどのかなの後でも折り返し、n-gram はキーの組で数える（`docs/measurement.md`・`docs/analysis.md`）。
- **［確認可］ 文字数を基準にした指標**：平均 IKI・正確率・WPM は、お題の文字数を基準にしていた。→ **解決済み**：日本語は文字数をかなの数、平均 IKI をキーあたりにした（`docs/measurement.md`）。
- **スマホ**：画面のキーボードでは keydown が正しく取れないことが多い。→ スマホ・タブレットには対応しないことに決めた（3 を参照）。

### 決める必要があること
