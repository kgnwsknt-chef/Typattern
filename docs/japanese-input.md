# 日本語入力の設計メモ

日本語のタイピング（ローマ字入力・かな配列）について、**なぜそう決めたか**と、まだ決まっていないことをまとめる。決まりそのものは、それぞれの文書に書いてあり、ここでは重ねて書かない。

| キー配列のページ（物理キーの番号・配列図・シフト面・試し打ち・割り当て表の書き方・登録・上書き・削除） | [layouts.md](layouts.md) |

## 1. 基本の方針と理由

- **IME（かな漢字変換）を使わない**：変換中の文字が何度も書き換わり、打鍵の記録や判定ができなくなるため。キーは keydown の `e.code`（押したキーの物理的な位置）で受け取り、かなへの変換と判定はすべてアプリの中で行う。OS の入力は US 配列の英字のまま（IME はオフ）で使う前提で、IME がオンのまま打たれたら受け付けずに注意を出す。
- **スマホ・タブレットには対応しない**：画面のキーボードでは `e.code` が正しく取れないため。
- **キーの同時押しには当面対応しない**（2026-10-20 に決めた。README にも明記）：前置・後置シフトなど、順に押す入力だけを扱う。キーはすべて1つずつ順に押したものとして判定・記録し、n-gram でも順に押したキーの組として数える。対応するなら、全部のキーの離した時刻の記録、平均 IKI とキーごとの間隔の定義、判定のタイミング（単独押しか同時押しかが決まるまで待つ）、割り当て表の書き方、キー配列のページの表示を決め直す必要がある。文字単位のもの（レベル・正確率・ランキング）はそのまま使える。
- **判定はお題に合わせる**：打つべきかなを読める打ち方の一覧を作り、押したキーがそのどれかの続きなら正解とする。表だけで機械的に変換すると `konnichiha` が「こんいちは」になるため。「ん」を `n` 1つで打てるか、「っ」を子音の重ねで打つかも、お題を見て決める。かな配列も同じ仕組み（`js/typer.js`）で、後置シフトのように次のキーを見ないと決まらない並びも、お題が分かっているので迷わない。
- **間違えたキーは英語と同じく残す**：直さずに先へ進め、Backspace で直す。正確率の式も英語とそろえる。
- **文字数は「かな1文字」、平均 IKI は「キーあたり」**：かな配列やローマ字では、1文字に必要なキーの数が配列や文字によって違うため、速さは「入力した文字数」と「キーストローク数」の両方で見る。平均 IKI は1キーあたりの時間、かなの速さは「かな/分」として別に出す。表示する漢字かな交じりの文の文字数は使わない。
- **`keyLayout` は論理配列**：どの文字がどのキーにあるか（QWERTY・かな配列など）を表す。物理配列（JIS・US）とは別で、区別したくなったら別の項目として足す。入力方式も別の項目にはせず、`"qwerty"`（日本語ならローマ字入力）か配列名を入れる。
- **ランキング・推移は配列ごとに分ける**：配列が違う記録を同じ順位で比べても意味がないため（区分は言語・モード・配列）。
- **お題は「表示する文」と「読み」を交互に書く**：打つのは読み。英語のお題を `.txt`（1行70文字前後で改行）にしたときに、日本語で読みが要るなら形式を見直すと決めていたため。お題には Shift を使う文字を入れず、記号は「、」「。」「ー」だけにする。

## 2. 物理キーの番号

物理キーの番号の決まりは、日本語に限らず使う（英語の記録・配列図にも使う）ので、`docs/layouts.md` の「物理キーの番号」に移した。

## 3. 日本語での events の使い方

記録の形（5要素の行・各欄の意味）は [storage.md](storage.md) の「`events`」。ここでは日本語で決めたことと、その理由を書く。

- **押した物理キーの番号を `"k"` の行に残す**：かな配列では、2キーで1かなになったりシフトがあったりして、文字から押したキーを逆算できないため。英語でも同じく残す（キーあたりの IKI やキーストローク数を出せ、記録の形が言語によらず同じになる）。
- **キーの単位（`"k"`）とかなの単位（`"+"` / `"-"`）を1本の記録に残す**：キーの IKI は `"k"` の行どうしの時刻の差、かなの速さは `"+"` の行から求める。
- **`"k"` の位置**は、そのキーを当てたかなの位置。打ちかけの `n`（ん）が次のキーで確定したときは、次のキーの位置は次のかな。
- **`"+"` の文字はお題のかな**：間違いのときも、打ったキーではなくお題のかなを入れ、判定を `0` にする（何を押したかは `"k"` の行で分かる）。
- **`"+"` の時刻は「そのかなを生んだ最後のキーの時刻」**：後置シフトのように次のキーで確定する場合も、確定した瞬間ではない。そのため日本語では、行の並び順と時刻の順が一致しないことがある（分析では時刻で並べ直す）。
- **`"-"` は確定したかなを消したときだけ**：打ちかけのキーを Backspace で消したときは `"k"` だけ。「しゃ」を `sha` で打った後の Backspace は2文字とも消える（`"-"` の文字は「しゃ」）。
- **判定の結果を残す理由**：判定の決まり（ローマ字の打ち方など）が後で変わっても、当時の判定が分かるようにするため。記録のページで1回分のグラフを出すときは、記録したキーを今の判定にもう一度通して再現し、再現した `"+"` の行が記録と合うときだけ使う（[records.md](records.md)）。

例（お題「しか」をローマ字で `shika`）：

```
[  0.0, "k", "22", 0, 1]   s
[150.2, "k", "26", 0, 1]   h
[290.5, "k", "18", 0, 1]   i
[290.5, "+", "し", 0, 1]   「し」が確定
[420.0, "k", "28", 1, 1]   k
[530.8, "k", "21", 1, 1]   a
[530.8, "+", "か", 1, 1]   「か」が確定
```

例（後置シフトの配列。お題「ぴ…」を `j` → `'` → 次のかなのキー）：

```
[  0.0, "k", "27", 0, 1]   j
[120.0, "k", "2b", 0, 1]   '
[260.0, "k", "28", 1, 1]   次のかなのキー（「j'」の続きではないと分かる）
[120.0, "+", "ぴ", 0, 1]   ここで「ぴ」を確定。時刻は最後のキー（'）の時刻
```

- **schemaVersion を 4 に上げ、3 以前の記録は扱わない**：`"k"` の行があることと `"+"` の時刻の定義を、版で明確にするため。新しいデータベース `typattern-records` を使い、3 以前の記録・書き出しファイルは読まない（消しもしない）。それまでの記録は少なかったので、新しく始めた。
- **データ量の見積もり**（1回 約300文字）：英語は約17KB、日本語のローマ字は約22KB、2打で1かなの配列は約19KB。1日10回を1年続けて約70MB で、IndexedDB の容量に十分収まる。

## 4. かな配列

キー配列に関すること（割り当て表の書き方・登録・上書き・削除・配列図・シフト面・試し打ち）は、決まりも理由も [layouts.md](layouts.md) に書く。タイピング画面での判定の決まりは [measurement.md](measurement.md) の「かな配列」。ここでは、それ以外の理由を書く。

- **最初に念頭に置いた配列は月見草配列**（前置・後置シフトのある、2打で1かなの配列）。
- **割り当ては「キーの並び → かな」の表で設定する**：決まりと理由は [layouts.md](layouts.md) の「割り当て表の書き方」。
- **書き出しファイルに配列も入れる**：別の PC に記録を移しても、記録を読み解けるようにするため。
- **割り当て表にないかなは、ミスとして飛ばす**：作りかけの配列でも打てるようにするため。直せないので未修正の間違いとして残り、正確率が下がる。
- **かな配列では手引き（次に打つキー）を出さない**：お題の読みはひらがなのまま出す。

## 5. 日本語の単語リスト

`wordlists/ja/basic1000.txt` の選び方（ファイルの先頭にも要点を書いてある）。

- **中身**：日本語の文章でよく使う語ちょうど1000語（名詞 483・動詞 204・形容詞と形容動詞 118・副詞 72・接続詞と言い回し 123。「しかし」「です。」なども含む。カタカナ語も含む）。
- **重なりを避ける**：読みが2かなの語は100語まで。読みが同じ語（同音語）や、読みの半分以上がほかの語と重なる語（「効果／効果的」「考え／考える」「始める／始まる」など）は、どちらか一方だけにする。
- **続けて押すキーの組を多く出す**：30キー（`11`〜`1a`・`21`〜`2a`・`31`〜`3a`）で続けて押すキーの組（30×30＝900通り）が、QWERTY のローマ字（手引きと同じ打ち方）と月見草配列（各かなを、判定で最初に選ぶ打ち方で打つ）の両方で、なるべく多く出るように選んだ。2かなの語や、読みが重なる語を減らした代わりに、残る語と重ならず、まだ出ていない組を増やす語（語尾が似やすい動詞・形容詞を避けて名詞を中心に）を入れた。単語の中の組だけを数える（スペースをまたぐ組は数えない）。
  - 900通りのうち出てくる組は、QWERTY 221（24.6%）、月見草配列 611（67.9%）、両方を合わせて 668（74.2%）（2026/10/24 の入れ替えの後に数え直した数）。ローマ字はほとんどが「子音＋母音」の並びなので、子音のキーが続く組はほとんど出ず、ローマ字だけでは大きく広げられない。
  - 月見草配列の数は、2026/10/21 に保存した割り当て表「月見草v2-kc-ed」で数えた。各かなは、タイピング画面の判定で最初に選ぶ打ち方（割り当て表から作った打ち方の一覧の最初のもの）で打つとした。1000語すべて、この割り当て表で打てる（表にないかなを含む語はない）。
- **2026/10/23 の入れ替え**：うぇ・うぃ・うぉ・きゃ・しぇ・ぎゅ・にょ・でぃ・ふぃ・ゔぉ・ゔぇ・ゔぃ を含む語がほとんどなかったので、ウェア・ウィンドウ・キャベツ・ウォーキング・観客・来客・シェフ・牛乳・牛肉・如実・女房・メディア・ディスク・オフィス・フィルム・ヴォーカル・ヴェール・ヴィンテージ の18語を足した。代わりに、読みがほかの語と重なる語（今度・今後・今回・電気・人気・半分・選手・感情・給料・量・急・医者・全体・改行・当時・気になる・手・に対して）を外した。外す語は、その語にしかないかなの並びやキーの並び（月見草配列）を持たず、まとめて外しても1000語から消える並びがないものを選んだ。足した語で、月見草配列のキーの並びが15種類増えた（上の数は入れ替えた後のもの）。
- **2026/10/24 の入れ替え**：読みが1かなの語（木・目・絵）は、単語の中で続けて押すキーの組がほとんど取れない（1つか0）ので、ビデオ・カフェ・スケッチに入れ替えた。どれも単語リストと読みが重ならず、まだ出ていない組を足す語（ローマ字の `eo`・`ec`、月見草配列の `iz`・`zk`・`wb`・`be` など）。外した3語の組は、ほかの語にも出てくるので消えない。上の数は、この入れ替えの後のもの（入れ替える前は QWERTY 218・月見草配列 607・両方 666）。
- **単語の間はスペースを打つ**：英語と同じ。実際の日本語の文章では漢字変換があり、ずっと続けて打つわけではないため。スペースはローマ字でもかな配列でもスペースキーで打つ（割り当て表になくてよい）。

## 6. まだ決まっていないこと

- **キーストローク数の数え方の残り**：
  - かな配列で、シフト用のキー単独の押下を何回と数えるか。
  - 1文字あたりのキーストローク数（KSPC）も出すか。
  - 英語の指標をどうするか。英語の平均 IKI は今も文字あたり（`result.keystrokes` は入力された文字の数で、Shift は数えない）。英語でも `"k"` の行があるので、日本語と同じくキーあたりにそろえることもできる。そろえないうちは、推移で英語と日本語を混ぜると尺度が違う（凡例に注意を出している）。
