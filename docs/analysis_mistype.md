# ミスタイプの分析

打ち間違いの傾向（どのキーを、どのキーと押し間違えたか）を記録から求めて、ミスタイプのページ（`mistype.html`）に出す決まり。集計は `js/mistype.js`、ページの処理は `js/mistype-page.js`。計測の決まり（タイピング中のミスの数え方）は `docs/measurement.md`、記録の形は `docs/storage.md`、n-gram の分析は `docs/analysis_iki.md`。

## ミスタイプのページ（`mistype.html`）

一番上のリンクの「ミスタイプ」（IKI と苦手な単語の間）から開く。上から次の順に並べる。数え方の決まり（使う記録・数える単位・打つべきだったキー・種類）は、この後の節に書く。

1. **データの絞り込み**：記録・IKI のページと共通（言語・配列・モード・期間。`docs/records.md`）。練習モード（苦手な単語）の回も入る。除くときは「モード」で「練習モード以外」を選ぶ。
2. **集計の要約**：総打鍵数（押したキーの数。Shift・Backspace・間違えたキーも数える。IKI のページと同じ）、ミスの打鍵の数（続けて起きたものも全部）、押し間違いの数（続けて起きたミスの最初。総打鍵数に対する割合も）、判定を再現できず数えなかった記録の数（あるときだけ）。
- **配列図の書き方**（3・4 共通。描き方は `js/key-map.js`、IKI のページのキーごとの IKI と同じ）：キー配列のページと同じ形の配列図で、各キーの左上に物理キーの番号（`1d`・`3a` など）、右上に QWERTY の文字（文字のないキーは下の段に名前）、右下に値を書く。絞り込みの「配列」でかな配列を選んでいるときは、キーの真ん中にそのキーだけを押したときのかな（シフトなし）を書き（QWERTY の文字は小さくする）、前置・後置シフトのキーを外形線の色で示す（キー配列のページと同じ。前置 = オレンジ、後置 = 紫）。英語の配列を選んでいるときは、キーの真ん中にそのキーの文字（Shift なし）を書く。「すべて」や QWERTY のときは、何も書かない。
3. **キーごとのストローク回数**（配列図）：キー配列のページと同じ形の配列図に、そのキーを押した回数を書き、多いほど濃い青で塗る（一番多いキーが一番濃い。n-gram の2次元ヒストグラムの回数と同じ色）。
4. **キーごとのミス率**（配列図）：ミス率 ＝ 押し間違い ÷ そのキーが打つべきキーだった回数。
   - 打つべきキーだった回数 ＝ そのキーを正しく押した回数 ＋ そのキーを打つべきところで押し間違えた回数（続けて起きたミスの2つ目以降は数えない）。
   - 高いほど濃い赤。全体のミス率（全キーの押し間違い ÷ 全キーの打つべきキーだった回数）の3倍で一番濃くする（飛び抜けて高いキーが1つあっても、ほかのキーの違いが見えるように）。
   - 打つべきキーだった回数が 20 回未満のキーは、率がぶれやすいので色を付けず、値を薄く書く。Shift・Backspace など、打つべきキーにならないキーは値を書かない。
   - キーにマウスを乗せると、押し間違いと打つべきキーだった回数を出す。
   - **ミス率の推移**：値のあるキーをクリック（または Enter）すると、そのキーを黒い太枠で囲み、配列図のすぐ下にそのキーのミス率の推移を描く。最初（と、選んでいたキーを絞り込みで打たなくなったとき）は、押し間違いの一番多いキー（同じなら打つべきキーだった回数の多いキー）。図の形・移動平均は IKI のページの「IKI の推移」の日付のときと同じ（`docs/analysis_iki.md`。描き方は `js/point-trend.js`）。
     - 横軸は日付だけ（このPCの日付。絞り込んだ最初の記録の日から最後の記録の日まで）。1回ごとだとそのキーを打つ回数が少なく、0% の点ばかりになって傾向が読めないため、回数の横軸は出さない。
     - 点 ＝ 1日の、そのキーの押し間違い ÷ 打つべきキーだった回数（%）。そのキーを打たなかった日は点がない。線 ＝ 直近 10 点の移動平均。
     - 縦軸は 0% から、描く点の最大（の 1.05 倍）まで（100% で頭打ち）。
     - 点にマウスを乗せると「2026/10/18：ミス率 7.2%（押し間違い 38 ／ 打つべきキーだった回数 527）」のように出す。
5. **押し間違いの種類**：種類ごとの数と割合（押し間違いの数に対する）を、多い順に表にする。
6. **打ち間違いの組**：「打つべきキー → 押したキー」ごとの回数・割合（押し間違いのうち組が分かるものに対する）と、その組の種類（種類ごとの回数。1種類だけなら名前だけ）。最初は回数の多い順。列の見出し（打つべきキー・押したキー・回数）をクリックで並べ替える。

7. **ミスが起きやすい並び**：「直前に正しく押したキー → 打つべきキー」（QWERTY の文字2つ）の並びごとに、打とうとした回数（正しく押した回数 ＋ 押し間違い）・押し間違い・ミス率を数える。
   - 数えるのは、直前のキーが正しい打鍵のときだけ（直前がミスや Backspace だと、何をしようとしていたか決めにくいため）。スペース・Backspace・Shift と同時に押したキーが絡む並びは除く（IKI のページと同じ）。
   - 「回数」（打とうとした回数の下限。5・10・20・50 回以上、初期値 10 回以上）で絞る。
   - 左に2次元ヒストグラム（IKI のページと同じ形。横軸 = 直前のキー、縦軸 = 打つべきキー）を、ミス率の色（0% は白に近い薄い赤、全体のミス率の3倍以上が一番濃い赤。データのないマスは白）で描く。マスにマウスを乗せると「17 回中 6 回押し間違い（35.3%）」のように出す。
   - 右に表（並び・回数・押し間違い・ミス率）。最初はミス率の高い順で、列の見出し（並び・回数・ミス率）をクリックで並べ替える。
   - マスをクリック（または Enter）すると、そのマスを枠で囲んで軸のラベルを強調し（IKI のページと同じ）、表のその行を強調して表の中をその行までスクロールする。表の行をクリックしたときも、2次元ヒストグラムのそのマスを同じように強調する。
8. **押し間違いの直前の間隔**：押し間違い（続けて起きたミスの最初）の直前の間隔と、正しい打鍵の間隔の分布を、同じ横軸で重ねて描く。
   - 押し間違いの直前の間隔 ＝ 押し間違えたキーと、その直前のキー（Shift は除く）の時刻の差。直前が Backspace のものは除く（直した後の打ち直しは、ふだんの打鍵と違うため）。
   - 正しい打鍵の間隔 ＝ 直前も正しい打鍵だった、正しい打鍵の間隔。
   - 横軸は 0〜設定の「分布の横軸の最大」（初期値 2000 ms。n-gram の分布と同じ。`docs/settings.md`）を 50 個の区間に分け、それ以上は一番右の区間に入れる。縦軸は、それぞれの回数を 100% とした割合（回数が大きく違うため）。
   - 正しい打鍵は薄い青の棒、押し間違いの直前は赤い線（階段状）。それぞれの中央値を、同じ色の縦の点線で示す。
   - 上に中央値と回数を書き、比べて一言添える。押し間違いの直前の中央値が、正しい打鍵の中央値の 0.9 倍より小さければ「急いで（リズムより先に）打って間違えることが多い」、1.1 倍より大きければ「迷って（手が止まってから）間違えることが多い」、その間なら「差は小さい：速さとは関係なく間違えている」。

- キーは QWERTY の文字で表す（日本語も押したキー。IKI のページと同じ）。Shift ありは Shift で出る文字（`T`・`!` など）、スペースは `Space`。

## 使う記録

新しく記録するものはない。生データ（`raws`）の `events` にある、次のものだけで求める。

- **押したキー**：`"k"` の行の物理キーの番号（`js/keys.js`）。
- **判定**：`"k"` の行の5番目（正解 `1`・ミス `0`）。
- **打っていた位置**：`"k"` の行の4番目（お題の何文字目か。日本語はかなの位置）と、`raws` の `text`（お題）。
- **時刻**と、その前後に押したキー。

## 数える単位：続けて起きたミスは、最初だけ数える

- ミスの打鍵から始まり、**正しい打鍵** か **Backspace** が来るまでに続いたミスを、1つのまとまりとする。
- 押し間違いとして数えるのは、まとまりの**最初のミスだけ**。どのキーを押し間違えたか（打つべきだったキーと押したキー）も、最初のミスで判定する。
- 2つ目以降のミスは押し間違いに数えない。最初のミスがどんな間違いだったか（下の「種類」）を見分ける手がかりにだけ使う。
- 理由：英語では1文字抜けると後ろが全部ずれてミスが続き、日本語でも押し間違いの続きのキーが次のかなに対してミスになることがある。2つ目以降の打鍵は、本人のつもりでは合っていることが多いため。
- **結果画面・ランキング・記録の「ミス」の数は変えない**（間違えたキーをすべて数える。`docs/measurement.md`）。最初だけ数えるのは、この分析の中だけ。計測の決まりと、これまでの記録の数をそのまま比べられるようにするため。

## 打つべきだったキーの求め方

- **英語**：お題のその位置の文字のキー（大文字や記号は Shift ＋ そのキー）。英語の配列の回は、割り当て表を逆に引いて、その文字を出すキーを求める（表にない文字は QWERTY のキー）。
- **日本語（ローマ字・かな配列）**：記録したキーを、タイピング中と同じ判定（`js/typer.js`）にもう一度通して、（英語の配列でローマ字を打った回は、記録したキーを割り当て表でその配列の文字に直してから通し、正解だった文字は割り当て表を逆に引いてキーにする）ミスしたときに正解だったキー（お題のかなを打てる並びの、次のキー）を求める（`Typer` の `expect`）。記録のページでランキングの回を再現するのと同じ方法（`js/session-view.js` の `replay`）。
  - 打ち方が複数あるとき（ローマ字の「し」= `si`・`shi`・`ci`、かな配列の「ぴゃ」= `j'e` または「ぴ」＋「ゃ」）は、正解だったキーが複数になる。数えるときは、**手引きが示す打ち方のキー**（ローマ字の手引きと同じ選び方。かな配列では割り当て表から作った一覧の最初の打ち方）を打つべきキーとする。
  - 再現した判定が記録と合わないとき（判定の決まりが後で変わった）や、その回の配列（かな配列・英語の配列）を削除したときは、その回は数えず、数えなかった回数をページに出す。
  - 押したキーが、お題のかなの別の打ち方の始まりだったときは、ミスにならない（正しい別の打ち方として受け付けるため）。この場合は押し間違いとして拾えない。そのまま打ち進めて別の打ち方として成り立たなければ、次のキーでミスになる。
- キーごとのミス率では、ミスを**打つべきだったキー**の側に数える（押したキーの側ではない）。

## 種類

最初のミスを、続く打鍵も手がかりにして次のように分ける。

### 英語（と、ローマ字のキー）

例はお題が `the` のとき。

上から順に調べ、最初に当たったものにする。

| 種類 | 例 | 見分け方 |
| --- | --- | --- |
| 順番の入れ替え | `teh` | 押したキーがお題の次の文字で、続けて打つべきだった文字を押した。日本語は、手引きの打ち方の次のキーを押し、続けて打つべきキーを押した |
| 抜け（英語のみ） | `te`…（h を飛ばした） | 押したキーがお題の次の文字で、続く打鍵がその次の文字（お題の終わりなら続きなし） |
| 重ね打ち・余分な1打（英語のみ） | `thhe`… | 直前と同じキーをもう一度押した、または続く打鍵が打つべきだった文字（1打余分に押してから続けた） |
| Shift の違い（英語のみ） | `The` のところで `the` | 押した物理キーは正しく、Shift の有無だけが違う |
| 隣のキー | `rhe`（t のところで r） | 押したキーが、打つべきキーの同じ段の左右、または上下の段のすぐ近く（キーの中心の横のずれが同じ段で 1 個分、上下の段で 1.3 個分まで。スペースの段は除く） |
| 左右の取り違え | f のところで j | 押したキーが、反対の手の同じ指のキー（数字・Q・A・Z の段の左から1〜10番目の列を左右で入れ替えたもの。q ↔ p、f ↔ j、z ↔ /） |
| その他 | | どれにも当たらない |
| 打つべきキーが分からない | | 打つべきキーを求められなかった（数に入れるが、組の一覧とキーのミス率には入れない） |

- 日本語の「抜け」「重ね打ち」は、キーの並びがかなの打ち方で変わるため、まだ見分けない（「その他」などに入る）。

### かな配列の前置シフト・後置シフト

前置シフト・後置シフトは、タイピング中の判定では特別扱いしない（割り当て表の「キーの並び → かな」の一つとして、お題を手がかりに判定する。`docs/measurement.md` の「かな配列」）。分析では、割り当て表からどのキーが前置・後置シフトかを求め（キー配列のページの配列図と同じ求め方。2打の並びの1打目・2打目に5回以上出てくるキー）、上の表の前（「順番の入れ替え」より先）に次の種類を調べる。例は前置シフト `;`、後置シフト `'`、「ぴ」= `j` → `'`、「ぱ」= `;` → `x` のとき。

シフトのキーは、ふつうのかなのキーを兼ねることが多い（例：月見草の `e`・`f`・`s`・`j`）。そのため、押した位置（かなの始まりか、打ちかけの後か）と続くキーから、シフトとして押した・押すべきだったと言えるときだけ、シフトの種類にする。言えないときは、上の表（隣のキーなど）で分ける。

| 種類 | 例 | 見分け方 |
| --- | --- | --- |
| 前置シフト忘れ | 「ぱ」で `;` を押さずに `x` | かなの始まりで、打つべきキーが前置シフトのキーのときに、その次に押すべきキーを押した |
| 後置シフト忘れ | 「ぴ」で `j` の後、`'` を押さずに次のかなのキー | 打ちかけの後で、打つべきキーが後置シフトのキーのときに、次のかなの始まりのキーを押した |
| シフトの取り違え | 「ぴ」で `j` の後、`'` でなく別の後置シフトのキー | かなの始まりで前置シフトのキーを押すべきところで別の前置シフトのキーを、または打ちかけの後で後置シフトのキーを押すべきところで別の後置シフトのキーを押した |
| 余計なシフト | シフトのいらないかなで、シフトのキーを1つ余分に押した | かなの始まりで前置シフトのキーを、または打ちかけの後で後置シフトのキーを押し、続けて打つべきだったキーを押した |

- 打つべきキーと押したキーの物理キーが同じでシフトの有無だけが違う「面の取り違え」は、かな配列では「前置シフト忘れ」「余計なシフト」に含まれるので、分けない。

- **後置シフトで最初のキーを押し間違えたとき**（「ぴ」で `j` のつもりで `k` を押した）：`k` がその場でミスになる（「ぴ」のどの打ち方の始まりにもならないため）。打つべきだったのは `j`、押したのは `k` と判定する。
  - 続けて押した後置シフトの `'` は、判定では次のかなに対して行われ、ミスになることがある。これは押し間違いの続きなので、上の「最初だけ数える」に当たり、別の押し間違いには数えない。
  - 割り当て表で押した並び（`k` ＋ `'`）を引けば、実際に打ったかな（例「ぽ」）も分かる。「『ぴ』のところで『ぽ』を打った（`j` → `k`）」のように出せる。
- **元のキーは正しく、後置シフトのキーを間違えた**（`j` の後に `;`）：2つ目のキーがミスになり、打つべきだったのは `'` と判定する。
- **分からないこと**
  - キーの同時押しには対応していないので、同時押しのシフトは対象外。
  - かな配列のシフトのキーを押してから離すまでの時間は記録していない。そのため「シフトを押すのが遅れた」と「押し忘れた」は区別できず、どちらも順番の違いか、足りないミスとして出る。

## まだ決まっていないこと

- 日本語の「抜け」「重ね打ち」の見分け方。
