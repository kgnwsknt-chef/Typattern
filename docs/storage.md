# 記録の保存形式（schemaVersion 3）

お題を最後まで打つたびに、その回の記録をブラウザの IndexedDB に保存する。1回の記録は **概要（`sessions`）** と **生データ（`raws`）** の2つに分け、同じ `id` で結び付ける。実装は `js/store.js`（保存・ランキングの取り出し・書き出し・読み込み）と `js/app.js`（記録の組み立て）。

- ランキングや推移グラフは、軽い概要だけを読む。
- n-gram の集計や後からの再分析は、生データを読む。
- 概要と生データは、必ず1つのトランザクションで一緒に書く（片方だけ残ることはない）。
- ランキングは保存しない。概要から毎回計算する。

## 版番号

| 名前 | 何の版か | 場所 |
| --- | --- | --- |
| `appVersion` | アプリのバージョン（`index.html` の `?v=`、画面右下の表示） | 概要の記録 |
| `schemaVersion` | 記録1件・書き出しファイルの形式の版。今は **3** | 概要の記録・書き出しファイル |
| `DB_VERSION` | IndexedDB の入れ物（保存場所・索引）の構造の版 | `js/store.js` のコードだけ |

**schemaVersion 1（旧形式）は扱わない。** 旧形式は別のデータベース（`typing-test`）に入っていて、アプリは読まない（消しもしない）。旧形式の書き出しファイルも読み込めない。

## 保存先

| 項目 | 値 |
| --- | --- |
| データベース名 | `typing-records` |
| `sessions` | 概要。キーは `id`。索引 `finishedAt`（日時順）、`rank`（下記） |
| `raws` | 生データ。キーは `id` |
| 範囲 | ブラウザ・サイトごと。`localhost:8000` と公開サイトは別々の記録になる |

索引 `rank` は `[lang, mode, keyLayout, result.avgIki]`。ランキングの区分（言語・モード・配列）ごとに、平均 IKI の小さい順に並ぶ。Top 30 はこの索引を小さい方から読み、正確率 95% 未満を飛ばして30件集めたところで止める。今回の順位とランキングに載る記録数は、その区分の概要だけを読んで数える（生データは読まない）。

ブラウザの閲覧データを消すと記録も消える。画面右上の「記録を書き出す」で JSON ファイルに保存し、「記録を読み込む」で戻せる。初回保存時に `navigator.storage.persist()` で、ブラウザに自動削除しないよう頼む。

## 概要（`sessions`）：1回1件、約0.3KB

```json
{
  "schemaVersion": 3,
  "id": "0b6c…（UUID）",
  "finishedAt": "2026-10-17T09:12:41.882Z",
  "appVersion": "11",
  "lang": "en",
  "mode": "normal",
  "keyLayout": "qwerty",
  "textId": "qwerty",
  "textLength": 646,
  "result": {
    "wpm": 72.4,
    "accuracy": 97.8,
    "timeSec": 38.762,
    "keystrokes": 652,
    "misses": 14,
    "uncorrected": 0,
    "avgIki": 60.1
  }
}
```

| フィールド | 内容 |
| --- | --- |
| `schemaVersion` | 形式の版（3） |
| `id` | 記録ごとの UUID。`raws` と同じ値。読み込み時の重複判定にも使う |
| `finishedAt` | 打ち終わりの日時（UTC, ISO 8601）。打ち始めは `finishedAt - result.timeSec` で求められるので持たない |
| `appVersion` | 記録したときのアプリのバージョン |
| `lang` | お題の言語（`en`、将来は `ja`） |
| `mode` | `"normal"`（文章）・`"short"`（短い文章）・`"words"`（単語）。IndexedDB の索引に true/false は使えないため文字列にしている |
| `keyLayout` | 論理キー配列（今は `"qwerty"` のみ）。画面右上の「配列」で選ぶ |
| `textId` | お題の題材名（`texts/index.json` の名前。例 `qwerty`）。単語モードは単語リスト名（例 `basic1000`） |
| `textLength` | お題の文字数 |
| `result` | 結果の数値。`wpm` `accuracy` は小数第1位（`accuracy` は最後にお題と合っていた文字の割合で、直したミスは含めない）、`timeSec` は ms 単位。`avgIki` は平均 IKI ＝ 経過時間 ÷（文字数 − 1）で 0.1ms 単位（文字数が1以下なら `null`）。`uncorrected` は終了時に直さず残った間違いの数。定義は `docs/scoring.md` |

## 生データ（`raws`）：1回1件、約3〜10KB

```json
{
  "id": "0b6c…（sessions と同じ）",
  "keyLayout": "qwerty",
  "text": "The QWERTY keyboard layout was …",
  "events": [[0, "+", "T", 0, 1], [182.4, "+", "h", 1, 1], [301.0, "+", "w", 2, 0], [455.2, "-", "w", 2, null], …],
  "intervals": [null, 182.4, 95.1, …],
  "missedPositions": [2]
}
```

| フィールド | 内容 |
| --- | --- |
| `id` | `sessions` と同じ UUID |
| `keyLayout` | 論理キー配列（概要と同じ値）。events は入力された文字なので、これがあれば生データだけで文字を物理キーの位置に変換できる。概要と必ず同時に書く |
| `text` | 打ったお題の文（改行・空白をまとめた後のもの）。お題ファイルが後で変わっても分かるように丸ごと残す |
| `events` | 全キー入力の記録（下記） |
| `intervals` | お題の位置ごとの最終的な打鍵間隔(ms, 0.1ms 単位)。「キーごとの間隔」や n-gram の元データ。間隔がない位置は `null`。`events` から計算できるが、集計を速くするため保存する |
| `missedPositions` | 一度でもミスしたお題の位置（0 始まり）の一覧。`events` から計算できるが同上 |

### `events`（全キー入力の記録）

入力欄の内容が変わるたびに1行記録する。**どの行も5要素にそろえ、使わない欄は `null`** にする（行の長さが違うと、種類を確かめずに5番目を読んだときに間違えやすく、表に変換しにくいため）。

| 番号 | 内容 |
| --- | --- |
| 1 | 経過時間(ms, 0.1ms 単位)。最初の1文字を 0 とする |
| 2 | 種類。`"+"` = 入力（add）、`"-"` = 削除 |
| 3 | `"+"`：入力した文字 ／ `"-"`：消した文字（実際に入力欄にあった文字。一度に複数消えたらまとめて入る） |
| 4 | `"+"`：入力した位置 ／ `"-"`：消した部分の先頭の位置（= 消した後の入力の長さ） |
| 5 | `"+"`：入力した時点の判定（正解 `1`、ミス `0`） ／ `"-"`：`null` |

- Backspace を押すたびに `"-"` が1行。押しっぱなし（キーリピート）は1回ずつ別の行。Ctrl + Backspace のように一度に複数文字消えたときは1行にまとまる。
- 中身が変わらない操作（空の入力欄での Backspace など）は記録しない。
- 判定を残すのは、判定ルール（日本語のローマ字判定など）が後で変わっても、当時の判定が分かるようにするため。
- 将来の種類（日本語で実際に押したキーを残すなど）も、5要素にそろえて足す。

## 書き出しファイル

```json
{
  "app": "typing-test",
  "schemaVersion": 3,
  "exportedAt": "2026-10-20T12:00:00.000Z",
  "sessions": [ …概要… ],
  "raws": [ …生データ… ]
}
```

- 1つのファイルで全記録を戻せる（ファイルを分けると、別々の時点のものを組み合わせて食い違う危険があるため）。
- 読み込み時、同じ `id` の記録と、概要と生データが揃っていない記録は飛ばす。 生データに `keyLayout` がないとき（前の書き出しファイル）は、概要の値で補う。
- `schemaVersion` が 3 のファイルを読み込む。2 のファイルは読み込むときに 3 に直す（正確率を計算し直す）。それ以外は読み込まない。

## 形式の版の履歴（`schemaVersion`）

| 版 | 内容 |
| --- | --- |
| 1 | 旧形式（扱わない） |
| 2 | 概要と生データに分割。`result.accuracy` は (打鍵数 − ミス) ÷ 打鍵数 |
| 3 | `result.accuracy` を、最後にお題と合っていた文字の割合に変更（直したミスは含めない） |

## データベースの版の履歴（`DB_VERSION`）

| 版 | 内容 |
| --- | --- |
| 1 | `sessions`・`raws` を作成。索引 `rank` は WPM 順 |
| 2 | 索引 `rank` を平均 IKI 順に作り直す。既存の記録の `result.avgIki` を新しい定義で計算し直し、`result.uncorrected` を生データから数えて足す（生データは変えない） |
| 3 | 既存の記録の `result.accuracy` を新しい定義（最後に合っていた文字の割合 ＝ (textLength − uncorrected) ÷ textLength）で計算し直し、`schemaVersion` を 3 にする（生データは変えない） |
| 4 | 既存の生データに `keyLayout` を足す（概要の値を書き写し、`id` の次に置く。ほかの中身は変えない） |

## 形式を変えるとき

- 既存の記録は書き換えない。新しいフィールドの追加だけなら `schemaVersion` はそのままでよい。
- 意味が変わる変更をするときは `schemaVersion` を上げ、扱い（移し替えるか、扱わないか）を決める。
- 保存場所や索引を変えるときは `DB_VERSION` を上げる。
- このファイルも一緒に更新する。
