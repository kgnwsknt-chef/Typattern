# 記録の保存形式

お題を最後まで打つたびに、その回の生データを1件の記録としてブラウザの IndexedDB に保存する。実装は `js/store.js`（保存・書き出し・読み込み）と `js/app.js`（記録の組み立て）。

## 保存先

| 項目 | 値 |
| --- | --- |
| データベース名 | `typing-test` |
| オブジェクトストア | `sessions`（キーは `id`、`finishedAt` に索引） |
| 範囲 | ブラウザ・サイトごと。`localhost:8000` と公開サイトは別々の記録になる |

ブラウザの閲覧データを消すと記録も消える。画面右上の「記録を書き出す」で JSON ファイルに保存し、「記録を読み込む」で戻せる（同じ `id` の記録は二重に入らない）。初回保存時に `navigator.storage.persist()` で、ブラウザに自動削除しないよう頼む。

## 1件の記録（schema 1）

```json
{
  "schema": 1,
  "id": "0b6c…（UUID）",
  "startedAt": "2026-10-17T09:12:03.120Z",
  "finishedAt": "2026-10-17T09:12:41.882Z",
  "appVersion": "10",
  "lang": "en",
  "short": false,
  "topic": "qwerty",
  "text": "The QWERTY keyboard layout was …",
  "result": {
    "wpm": 72.4,
    "accuracy": 97.8,
    "timeSec": 38.762,
    "keystrokes": 652,
    "misses": 14,
    "avgIki": 59.3
  },
  "missedPositions": [5, 88, 89],
  "intervals": [null, 182.4, 95.1, …],
  "events": [[0, "+", "T", 0, 1], [182.4, "+", "h", 1, 1], [301.0, "+", "q", 2, 0], [455.2, "-", "q", 2], …]
}
```

| フィールド | 内容 |
| --- | --- |
| `schema` | この形式の版。形式を変えるときは上げ、古い版の読み方を残す |
| `id` | 記録ごとの UUID。読み込み時の重複判定に使う |
| `startedAt` / `finishedAt` | 打ち始め（最初の1文字）と打ち終わりの日時（UTC, ISO 8601） |
| `appVersion` | 記録したときのアプリのバージョン（`index.html` の `?v=` の番号） |
| `lang` / `short` / `topic` | お題の言語・短縮版かどうか・題材名（`texts/index.json` の名前） |
| `text` | 打ったお題の文（改行・空白をまとめた後のもの）。お題ファイルが後で変わっても分かるように丸ごと残す |
| `result` | 結果画面の値。`wpm` `accuracy` は小数第1位、`timeSec` は ms 単位、`avgIki` は 0.1ms 単位。定義は `docs/scoring.md` |
| `missedPositions` | 一度でもミスしたお題の位置（0 始まり）の一覧 |
| `intervals` | お題の位置ごとの最終的な打鍵間隔(ms, 0.1ms 単位)。「キーごとの間隔」や n-gram の元データ。間隔がない位置は `null` |
| `events` | 全キー入力の記録（下記） |

### `events`（全キー入力の記録）

入力欄の内容が変わるたびに、何が起きたかを時刻つきで1行ずつ残す。この記録とお題の文があれば、ほかの値はすべて計算し直せる。

| 形 | 意味 |
| --- | --- |
| `[t, "+", 文字, 位置, ok]` | 文字を1つ入力した。`ok` は入力した時点の判定（正解 1、ミス 0） |
| `[t, "-", 消した文字列, 位置]` | Backspace などで消した。`位置` は消した部分の先頭（= 消した後の入力の長さ） |

- `t` は最初の1文字からの経過時間(ms, 0.1ms 単位)。最初の1文字が `0`。
- 1回の入力で複数文字が入ったときは、同じ `t` の `"+"` が並ぶ。
- `ok` を残すのは、判定ルール（日本語のローマ字判定など）が後で変わっても、当時の判定が分かるようにするため。

## 形式を変えるとき

- 既存の記録は書き換えない。新しいフィールドの追加だけなら `schema` はそのままでよい。
- 意味が変わる変更をするときは `schema` を上げ、読み込み処理で古い版も扱えるようにする。
- このファイルも一緒に更新する。
