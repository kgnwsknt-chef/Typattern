# 記録の保存形式（schemaVersion 4）

お題を最後まで打つたびに、その回の記録をブラウザの IndexedDB に保存する。1回の記録は **概要（`sessions`）** と **生データ（`raws`）** の2つに分け、同じ `id` で結び付ける。実装は `js/store.js`（保存・ランキングの取り出し・書き出し・読み込み）と `js/app.js`（記録の組み立て）。

- ランキングや推移グラフは、軽い概要だけを読む。
- n-gram の集計や後からの再分析は、生データを読む。
- 概要と生データは、必ず1つのトランザクションで一緒に書く（片方だけ残ることはない）。
- ランキングは保存しない。概要から毎回計算する。

## 版番号

| 名前 | 何の版か | 場所 |
| --- | --- | --- |
| `appVersion` | アプリのバージョン（`index.html` の `?v=`、各ページ左上のロゴの横の表示） | 概要の記録 |
| `schemaVersion` | 記録1件・書き出しファイルの形式の版。今は **4** | 概要の記録・書き出しファイル |
| `DB_VERSION` | IndexedDB の入れ物（保存場所・索引）の構造の版 | `js/store.js` のコードだけ |

**schemaVersion 3 以前の記録は扱わない。** 3 以前の記録は別のデータベース（2〜3 は `typing-records`、1 は `typing-test`）に入っていて、アプリは読まない（消しもしない）。3 以前の書き出しファイルも読み込めない。

## 保存先

| 項目 | 値 |
| --- | --- |
| データベース名 | `typattern-records` |
| `sessions` | 概要。キーは `id`。索引 `finishedAt`（日時順）、`rank`（下記） |
| `raws` | 生データ。キーは `id` |
| `layouts` | 登録したキー配列（下記）。キーは `id`（配列名） |
| 範囲 | ブラウザ・サイトごと。`localhost:8000` と公開サイトは別々の記録になる |

索引 `rank` は `[lang, mode, keyLayout, result.avgIki]`。ランキングの区分（言語・モード・配列）ごとに、平均 IKI の小さい順に並ぶ。Top 30 はこの索引を小さい方から読み、正確率 95% 未満を飛ばして30件集めたところで止める。今回の順位とランキングに載る記録数は、その区分の概要だけを読んで数える（生データは読まない）。

ブラウザの閲覧データを消すと記録も消える。各ページ下部の「記録を書き出す」で JSON ファイルに保存し、「記録を読み込む」で戻せる。初回保存時に `navigator.storage.persist()` で、ブラウザに自動削除しないよう頼む。

## 概要（`sessions`）：1回1件、約0.3KB

```json
{
  "schemaVersion": 4,
  "id": "0b6c…（UUID）",
  "finishedAt": "2026-10-17T09:12:41.882Z",
  "appVersion": "29",
  "lang": "en",
  "mode": "normal",
  "keyLayout": "qwerty",
  "textId": "qwerty",
  "textLength": 646,
  "result": {
    "wpm": 72.4,
    "accuracy": 97.8,
    "timeSec": 38.762,
    "keystrokes": 652,
    "misses": 14,
    "uncorrected": 0,
    "avgIki": 60.1
  }
}
```

| フィールド | 内容 |
| --- | --- |
| `schemaVersion` | 形式の版（4） |
| `id` | 記録ごとの UUID。`raws` と同じ値。読み込み時の重複判定にも使う |
| `finishedAt` | 打ち終わりの日時（UTC, ISO 8601）。打ち始めは `finishedAt - result.timeSec` で求められるので持たない |
| `appVersion` | 記録したときのアプリのバージョン |
| `lang` | お題の言語（`en` 英語・`ja` 日本語） |
| `mode` | `"normal"`（文章）・`"short"`（短い文章）・`"words"`（単語）。IndexedDB の索引に true/false は使えないため文字列にしている |
| `keyLayout` | キー配列。`"qwerty"`（英語は QWERTY、日本語はローマ字入力）か、登録したかな配列の配列名（`layouts` の `id`。日本語のみ）。画面上部の「配列」で選ぶ |
| `textId` | お題の題材名（`texts/index.json` の名前。例 `qwerty`）。単語モードは単語リスト名（例 `basic1000`） |
| `textLength` | お題の文字数（日本語は読みのかなの数） |
| `result` | 結果の数値。`wpm` `accuracy` は小数第1位（`accuracy` は最後にお題と合っていた文字の割合で、直したミスは含めない）、`timeSec` は ms 単位。`avgIki` は平均 IKI ＝ 経過時間 ÷（文字数 − 1）で 0.1ms 単位（文字数が1以下なら `null`）。`uncorrected` は終了時に直さず残った間違いの数。日本語では `wpm` は `null` で、代わりに `kanaPerMin`（かな/分、小数第1位）と `correctKeys`（最後に残った正しいかなを打ったキーの数。平均 IKI の分母）を持ち、`avgIki` ＝ 経過時間 ÷（`correctKeys` − 1）。`keystrokes` は日本語では押したキーの数（Shift・Backspace を除く）、`misses` は間違えたキーの数。定義は `docs/measurement.md` |

## 生データ（`raws`）：1回1件、約3〜10KB

```json
{
  "id": "0b6c…（sessions と同じ）",
  "keyLayout": "qwerty",
  "text": "The QWERTY keyboard layout was …",
  "events": [[-95.3, "k", "30", 0, null], [0, "k", "15", 0, 1], [0, "+", "T", 0, 1], [182.4, "k", "26", 1, 1], [182.4, "+", "h", 1, 1], [301.0, "k", "12", 2, 0], [301.0, "+", "w", 2, 0], [455.2, "k", "0d", 3, null], [455.2, "-", "w", 2, null], …],
  "intervals": [null, 182.4, 95.1, …],
  "missedPositions": [2]
}
```

| フィールド | 内容 |
| --- | --- |
| `id` | `sessions` と同じ UUID |
| `keyLayout` | キー配列（概要と同じ値）。概要と必ず同時に書く |
| `text` | 打ったお題の文（改行・空白をまとめた後のもの）。お題ファイルが後で変わっても分かるように丸ごと残す |
| `events` | 全キー入力の記録（下記） |
| `intervals` | お題の位置ごとの最終的な打鍵間隔(ms, 0.1ms 単位)。英語は結果画面の「キーごとの間隔」の元データ。日本語はかなごとの間隔（定義は `docs/measurement.md`。結果画面のグラフはキーごとなので、これは使わない）。間隔がない位置は `null`。`events` から計算できるが、集計を速くするため保存する（n-gram は `events` の `"k"` の行から数える） |
| `missedPositions` | 一度でもミスしたお題の位置（0 始まり）の一覧。`events` から計算できるが同上 |

### `events`（全キー入力の記録）

キーを押すたびに `"k"` の行を、入力欄の内容が変わるたびに `"+"` / `"-"` の行を記録する。**どの行も5要素にそろえ、使わない欄は `null`** にする（行の長さが違うと、種類を確かめずに5番目を読んだときに間違えやすく、表に変換しにくいため）。

| 番号 | 内容 |
| --- | --- |
| 1 | 経過時間(ms, 0.1ms 単位)。最初の1文字を入力したキーを押した時刻を 0 とする |
| 2 | 種類。`"k"` = キーを押した（key）、`"u"` = Shift を離した（up）、`"+"` = 入力（add）、`"-"` = 削除 |
| 3 | `"k"`・`"u"`：物理キーの番号（下記） ／ `"+"`：入力した文字 ／ `"-"`：消した文字（実際に入力欄にあった文字。一度に複数消えたらまとめて入る） |
| 4 | `"k"`・`"u"`：押した（離した）時点で打っている位置（= その時点の入力の長さ） ／ `"+"`：入力した位置 ／ `"-"`：消した部分の先頭の位置（= 消した後の入力の長さ） |
| 5 | `"k"`・`"+"`：その時点の判定（正解 `1`、ミス `0`。Shift と Backspace の `"k"` は `null`） ／ `"u"`・`"-"`：`null` |

- **`"+"` の時刻**は「その文字を生んだ最後のキーを押した時刻」。英語では、その文字のキーの `"k"` の行と同じ時刻になる（大文字は Shift ＋ キーで、最後はそのキー）。
- **`"k"` の行**：押したキーの物理的な位置（`e.code`）を、物理キーの番号（2桁の「行＋列」。「1」= `01`、Q = `11`、A = `21`、Z = `31`、左 Shift = `30`、右 Shift = `3c`、Backspace = `0d`、スペース = `45`（仮）。対応表は `js/keys.js`、決まりは `docs/japanese-input.md`）にして残す。OS の入力設定（US／JIS）に左右されない。
  - 番号のないキー（Ctrl・Alt・矢印・Enter・Tab・Esc など）と、Ctrl・Alt などと一緒に押したキー（Ctrl + Backspace を除く）は記録しない。
  - 押しっぱなし（キーリピート）は1回ずつ別の行。ただし Shift のキーリピートは記録しない（押した1回だけ）。入力欄が変わらなかったキー（空の入力欄での Backspace など）も残す。
  - 計測開始前に押したキーは、開始の打鍵と、そのとき押したままの Shift だけを残す（Shift は負の時刻になる）。
- **`"u"` の行**：Shift を離したときだけ記録する（どのキーを Shift と同時に押したかを分かるようにするため。n-gram で使う）。入力欄から外れたときに押したままの Shift も、離したことにする。計測開始前と終了後は記録しない。
- Backspace を押すたびに `"-"` が1行。Ctrl + Backspace のように一度に複数文字消えたときは1行にまとまる。中身が変わらない操作では `"-"` を出さない。
- 判定を残すのは、判定ルール（日本語のローマ字判定など）が後で変わっても、当時の判定が分かるようにするため。
- 将来の種類も、5要素にそろえて足す。日本語の行の使い方は `docs/japanese-input.md`。

## 登録したキー配列（`layouts`）：1配列1件

キー配列のページ（`layouts.html`）で割り当て表を読み込み、「この配列を保存する」で保存したかな配列。最初から入っている QWERTY は保存しない（コードの中にある）。

```json
{
  "id": "tsukimisou-v2",
  "name": "tsukimisou-v2",
  "type": "kana",
  "entries": [["j", "っ"], ["j'", "ぴ"], ["j'e", "ぴゃ"], …],
  "source": "j xtu\nj' pi\nj'e pya\n…",
  "savedAt": "2026-10-18T09:00:00.000Z"
}
```

| フィールド | 内容 |
| --- | --- |
| `id` | 配列名。利用者が自由に付ける（版を付けるなら名前に入れる。例 `tsukimisou-v2`）。その配列で打った記録の `keyLayout` にこの値が入る。最初から入っている配列の名前（`qwerty`。大文字・小文字は区別しない）は使えない |
| `name` | 表示する名前（今は `id` と同じ） |
| `type` | 配列の種類。今は `"kana"`（キーの並び → かなの割り当て表）だけ |
| `entries` | 割り当て表。`[キーの並び, かな]` の配列。キーの並びは US キーボードの QWERTY の文字で書く（Shift ありの文字は Shift ＋ そのキー）。同じキーの並びは1つだけ |
| `source` | 読み込んだときの割り当て表の文字列（ローマ字で書いたならローマ字のまま）。キー配列のページで、フォームに出し直すのに使う。判定や配列図には `entries` を使う。これを足す前に保存した配列にはない |
| `savedAt` | 保存した日時（UTC, ISO 8601） |

- 同じ名前で保存し直すと上書きする（確かめてから）。ただし、その配列で打った記録（`sessions` の `keyLayout` が同じもの）があるときは上書きできない。記録がどの割り当てで打ったものか分からなくならないようにするため。
- 削除は、その配列で打った記録があってもできる。記録は消さずに残り（`keyLayout` は配列名のまま）、記録ページの絞り込みでは「配列名（削除済）」と出す。

## 書き出しファイル

```json
{
  "app": "typattern",
  "schemaVersion": 4,
  "exportedAt": "2026-10-20T12:00:00.000Z",
  "sessions": [ …概要… ],
  "raws": [ …生データ… ],
  "layouts": [ …登録したキー配列… ]
}
```

- 1つのファイルで全記録と登録したキー配列を戻せる（ファイルを分けると、別々の時点のものを組み合わせて食い違う危険があるため。別の PC に記録を移しても、記録を読み解けるようにするため）。
- 記録もキー配列もないときは書き出さない。
- 読み込み時、同じ `id` の記録と、概要と生データが揃っていない記録は飛ばす。
- キー配列は、同じ名前のものがなければ足す。同じ名前で中身（`entries`）も同じなら飛ばす。中身が違うときは今のものを残し、読み込まなかった配列名を知らせる。
- `layouts` がないファイル（キー配列を保存できるようになる前の書き出し）も読み込める。項目を足しただけなので `schemaVersion` は 4 のまま。
- `schemaVersion` が 4 のファイルだけを読み込む。3 以前のファイルは読み込まない。

## 形式の版の履歴（`schemaVersion`）

| 版 | 内容 |
| --- | --- |
| 1 | 旧形式（扱わない） |
| 2 | 概要と生データに分割。`result.accuracy` は (打鍵数 − ミス) ÷ 打鍵数 |
| 3 | `result.accuracy` を、最後にお題と合っていた文字の割合に変更（直したミスは含めない） |
| 4 | `events` にキーの行 `"k"` を足し、`"+"` の時刻を「その文字を生んだ最後のキーの時刻」にした。新しいデータベース `typattern-records` に保存し、書き出しファイルの `app` を `"typattern"` にした。3 以前は扱わない |

## データベースの版の履歴（`DB_VERSION`）

`typattern-records` の版。

| 版 | 内容 |
| --- | --- |
| 1 | `sessions`（索引 `finishedAt`・`rank`）・`raws` を作成 |
| 2 | 登録したキー配列の保存場所 `layouts` を足す（記録は変えない） |

3 以前の記録が入っている旧データベース `typing-records` は版 4 まで（版 1 で作成、2 で索引 `rank` を平均 IKI 順に、3 で正確率の計算し直し、4 で生データに `keyLayout` を追加）。

## 形式を変えるとき

- 既存の記録は書き換えない。新しいフィールドの追加だけなら `schemaVersion` はそのままでよい。
- 意味が変わる変更をするときは `schemaVersion` を上げ、扱い（移し替えるか、扱わないか）を決める。
- 保存場所や索引を変えるときは `DB_VERSION` を上げる。
- このファイルも一緒に更新する。

## 今後の構想

- **ファイル同期**：記録の保存先は IndexedDB を本体にし、パソコンの Chrome/Edge では File System Access API で実ファイルにも同期する機能を後で足す、という計画。
